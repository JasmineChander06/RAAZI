## What is RAAZI?

RAAZI is a full-stack AI detective game where players interrogate suspects, examine clues, and deduce culprits in richly atmospheric mystery scenarios. The name nods to the ancient Islamic polymath Ibn al-Razi — a master of analytical reasoning.

Every case is **dynamically generated by Gemini AI** and solved using real computer-science algorithms running live in the browser and on the server:

- **Bayesian Inference** — suspect probabilities update in real-time as clues are discovered
- **BFS/DFS Graph Traversal** — the clue network is explored algorithmically to surface hidden connections
- **Shannon Entropy + Information Gain** — the Decision Engine ranks which question to ask next for maximum deductive value
- **NLP Intent Classification** — every investigator message is parsed server-side to detect interrogations, clue submissions, formal accusations, and more

## 🧠 AI Engine — How It Works

### 1. Bayesian Posterior Update

Each suspect starts with a **prior probability** assigned by Gemini. As clues are discovered, the posterior is recalculated using the full product of likelihoods:

```
P(Suspect_i | Clues) ∝ P(Suspect_i) × ∏ P(Clue_k | Suspect_i)
```

Each `ClueNode` stores a `likelihoods` map `{ suspectId → float [0.08, 0.95] }` representing how strongly that evidence implicates each suspect. After every discovered clue, all posteriors are renormalized to sum to 1.

**Code:** [`src/engine/aiAlgorithms.ts → recomputePosteriorFromEvidence()`](src/engine/aiAlgorithms.ts)

---

### 2. Shannon Entropy Decision Engine

The **Decision Engine** ranks candidate questions by **Expected Information Gain**:

```
IG(Q) = H(S) − E[H(S | Q)]
     = H(S) − [P(Q=yes) × H(S | Q=yes) + P(Q=no) × H(S | Q=no)]
```

Where `H(S) = − Σ P(sᵢ) × log₂(P(sᵢ))` is the current Shannon entropy over suspect posteriors.

Each `CandidateQuestion` holds two likelihood maps — `positiveLikelihoods` and `negativeLikelihoods` — to simulate both outcomes. The question with the highest information gain (most entropy reduction) is surfaced first.

**Code:** [`src/engine/aiAlgorithms.ts → rankNextQuestions()`](src/engine/aiAlgorithms.ts)

---

### 3. BFS / DFS Clue Graph Traversal

Clues form a **connected undirected graph** via `connectedNodeIds`. The `traverseClueGraph()` function supports:

- **BFS** — breadth-first, explores all clues at each distance layer first
- **DFS** — depth-first (iterative stack), dives deep into one chain before backtracking

The traversal outputs:
- Ordered `steps[]` with depth and parent tracking
- `edgesTraversed[]` for rendering the graph
- `strongestSuspectLinks[]` — the highest-likelihood clue implicating each suspect

**Code:** [`src/engine/aiAlgorithms.ts → traverseClueGraph()`](src/engine/aiAlgorithms.ts)

---

### 4. NLP Intent Classification (Server-Side)

Every investigator message is sent to Gemini on the server via `/api/investigate/turn`. Gemini performs:

| Classification | What it detects |
|---------------|-----------------|
| `interrogate` | Questioning a suspect's alibi or motive |
| `submit_clue` | Player submitting a physical field observation |
| `analyze_connection` | Asking about links between evidence |
| `request_hint` | Asking for investigative guidance |
| `accuse` | A formal final accusation ("I accuse X") |
| `general_query` | Explanation or summary request |

A **deterministic regex layer** (`detectExplicitAccusation()`) runs in parallel as a fallback to catch accusation patterns that the AI might miss.

---

### 5. Oracle Hints

The Oracle generates contextual hints without calling Gemini, by combining:

- Shannon entropy of current suspect distribution
- BFS traversal to find the strongest suspect-to-clue link
- Identification of unrevealed hidden clues and their connected parents
- Information-gain–ranked next question from the Decision Engine

**Code:** [`src/engine/oracleHints.ts → generateOracleHint()`](src/engine/oracleHints.ts)

## 🔄 Data Flow & Workflows

### Case Generation Flow

```
User clicks "New Case" → NewCaseModal
        │
        ▼ POST /api/cases/generate
        │   { era, themePrompt, difficulty, ownerId }
        │
        ▼ server.ts
        ├── Calls Gemini API (generateWithRetry)
        │   └── Primary: gemini-4-hydrogen (LOW thinking)
        │       Fallback: gemini-3.1-flash-lite (MINIMAL thinking)
        │
        ├── Parses JSON response:
        │   └── suspects (4), clues (5), candidateQuestions (3), synopsis, culpritId
        │
        ├── Normalizes priorProbabilities → sum to 1.0
        ├── Builds ClueNode objects with likelihoodMaps
        ├── Runs recomputePosteriorFromEvidence() (Bayesian pass)
        ├── Runs rankNextQuestions() (Information Gain ranking)
        └── Returns { caseData, clues, messages }
        │
        ▼ App.tsx (client)
        ├── If logged in → saveNewCaseToFirestore()
        └── Sets: activeCase, clues, messages, suggestedPrompts
```

---

### Investigation Turn Flow

```
User types message → DetectiveChamber
        │
        ▼ handleSubmitTurn()
        ├── Optimistic UI: append userTurn to messages
        │
        ▼ POST /api/investigate/turn
        │   { caseData, clues, messages, userInput, mode }
        │
        ▼ server.ts
        ├── detectExplicitAccusation() — regex accusation check
        ├── Calls Gemini API (NLP analysis)
        │   └── Returns: intent, entities, revealClueId, accuseSuspectId,
        │               newClueLikelihoods, raaziReply, suggestedPrompts
        │
        ├── If mode === 'clue':
        │   └── Build new ClueNode from user input + AI likelihoods
        ├── If mode === 'query' && revealClueId:
        │   └── Mark hidden clue as discovered
        │
        ├── recomputePosteriorFromEvidence() → updatedSuspects
        ├── rankNextQuestions() → rankedDecisions
        └── Returns full InvestigateTurnPayload
        │
        ▼ App.tsx (client)
        ├── Appends raaziTurn to messages
        ├── Updates clues, suspects, suggestedPrompts, activeCase
        ├── If logged in → persistInvestigationStep() → Firestore
        └── If accuseSuspectId → handleConfirmAccusation()
```

---

### Accusation & Verdict Flow

```
Formal accusation detected
        │
        ▼ handleConfirmAccusation(suspectId)
        ├── Compare accusedId vs caseData.culpritId
        ├── Build closing InvestigationTurn (verdict message)
        ├── Set case status → 'solved'
        │
        ├── If correct AND stageId exists:
        │   ├── Unlock next campaign stage
        │   ├── If logged in → recordCampaignStageCompletion() → Firestore
        │   └── writeGuestProgress() → localStorage
        │
        └── If logged in → finalizeCaseAccusation() → Firestore
```

---

### Oracle Hint Flow (No Gemini Call)

```
User clicks "Consult Oracle"
        │
        ▼ generateOracleHint({ activeCase, clues, rankedDecisions })
        ├── calculateShannonEntropy() → current entropy bits
        ├── traverseClueGraph() BFS from first discovered clue
        │   └── → strongestSuspectLinks[]
        ├── Build candidate hints pool:
        │   ├── Hidden clue proximity hints (connected to discovered parents)
        │   ├── Decision Theory hint (top information-gain question)
        │   ├── Bayesian alibi cross-check hint
        │   └── Final verdict hint (if all clues found)
        ├── Filter out previousHint (avoid repetition)
        └── Return randomly selected hint
```

## 🌐 API Reference

### `POST /api/cases/generate`

Generates a complete mystery case using Gemini.

**Request body:**
```json
{
  "era": "1928 English Country Estate · Manor Murder",
  "themePrompt": "A wealthy patron found poisoned behind a locked door",
  "difficulty": "Adept",
  "ownerId": "user_uid_or_guest"
}
```

**Response:**
```json
{
  "caseData": { ...DetectiveCase },
  "clues": [ ...ClueNode[] ],
  "messages": [ ...InvestigationTurn[] ]
}
```

---

### `POST /api/investigate/turn`

Processes one investigation turn — NLP analysis + Raazi's response.

**Request body:**
```json
{
  "caseData": { ...DetectiveCase },
  "clues": [ ...ClueNode[] ],
  "messages": [ ...InvestigationTurn[] ],
  "userInput": "Question Hargreaves about the missing letter",
  "mode": "query",
  "clueTitle": null,
  "clueCategory": null,
  "askedQuestionId": "q_2"
}
```

**Response (`InvestigateTurnPayload`):**
```json
{
  "raaziReply": "The inkstained glove found near...",
  "nlpAnalysis": {
    "intent": "interrogate",
    "extractedEntities": ["Hargreaves", "letter"],
    "referencedSuspectIds": ["suspect_2"],
    "summary": "Investigator questions suspect alibi"
  },
  "discoveredClue": null,
  "revealedClueIds": ["clue_4"],
  "updatedSuspects": [ ...Suspect[] ],
  "rankedDecisions": [ ...DecisionRank[] ],
  "suggestedPrompts": ["Check the study window latch", "..."],
  "accuseSuspectId": null,
  "askedQuestionId": "q_2"
}
```

---

### Gemini Model Strategy

The server uses a **3-attempt retry ladder** with exponential backoff:

| Attempt | Model | Thinking Level | Delay |
|---------|-------|---------------|-------|
| 1 | `gemini-4-hydrogen` | LOW | 0ms |
| 2 | `gemini-4-hydrogen` | LOW | 500ms |
| 3 | `gemini-3.1-flash-lite` | MINIMAL | 400ms |

Transient errors (503, 429, RESOURCE_EXHAUSTED) trigger retry; other errors fail fast.

## 🎵 Ambient Audio Engine

The `AmbientAudioEngine` class builds a fully procedural soundscape using the **Web Audio API** — no audio files needed.

### Soundscapes

| Mode | Character | Notes |
|------|-----------|-------|
| `violin` | Dark, tense, ancient-Hijaz | D3, F3, E3, C#3 — Dorian modal |
| `chimes` | Crystalline, ethereal | D4, F4, G#4, A4, C5, D5 — pentatonic shimmer |

### Signal Chain

```
Oscillators (OscillatorNode)
      │
      ▼
  Envelope (GainNode — attack / release)
      │
      ▼
  Dark Delay (DelayNode 0.48s, Feedback 0.42)
      │  └── BiquadFilter (lowshelf damping)
      ▼
  Brown Noise (AudioBufferSourceNode → BiquadFilter)
      │
      ▼
  Master Gain (fade in/out)
      │
      ▼
  AudioContext.destination (speakers)
```

**Code:** [`src/engine/ambientAudio.ts`](src/engine/ambientAudio.ts)

## 🗺️ Campaign Map System

The campaign is organized into **3 mystery categories**, each with **3 hand-authored stages** of increasing difficulty:

| Category | Stage 1 (Easy/Novice) | Stage 2 (Medium/Adept) | Stage 3 (Hard/Master) |
|----------|----------------------|------------------------|------------------------|
| **Manor Murder** | Blackwood Manor | The Velvet Cipher | The Obsidian Heir |
| **Ancient Intrigue** | The Alexandria Observatory | Silk Road Poison | The Pharaoh's Dagger |
| **Heist** | The Montpellier Diamond | The Shanghai Vault | The Cardinal's Codex |

### Progression Rules

- Stages unlock **sequentially** within each category
- Completing a stage (correct accusation) unlocks the next
- Progress is synced to **Firestore** (logged-in users) or **localStorage** (guests)
- On login, local guest progress is merged with the cloud profile

**Code:** [`src/data/campaignCases.ts`](src/data/campaignCases.ts)

## 🧰 Tech Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|

| **Styling** | TailwindCSS 4 | Utility-first CSS |
| **Animation** | Motion (Framer Motion) | UI transitions and animations |

| **Database** | Firebase Firestore | Real-time case/clue persistence |
| **Auth** | Firebase Authentication | Google OAuth + guest sessions |
| **Audio** | Web Audio API | Procedural ambient soundscapes |
| **Algorithms** | Pure TypeScript | Bayesian, Shannon entropy, BFS/DFS |
